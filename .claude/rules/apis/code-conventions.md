# API — Code Conventions

- **Response envelope**: never hand-wrap in a controller — return the DTO/entity and let the global `TransformInterceptor` produce `{ success, status, data }`. The exceptions that legitimately use `@Res()` — `cvs.controller.ts` `downloadCV` (file stream) and `auth.controller.ts` `verifyEmail` (redirect) — are correct uses, not violations; don't add a third one without a similarly hard requirement (binary stream / redirect).
- **Pagination**: every paginated service method returns `{ items, pagination: { page, limit, total, totalPages } }`. This is 100% consistent today across `candidates`, `notifications`, `ai-usage-logs`, `job-postings`, `interviews`, `applications` — match it exactly for any new paginated method.
- **Error messages**: user-facing throws (`HttpException`/`BadRequestException`/etc.) are in Vietnamese; internal/log-only messages stay in English. `VALIDATION_MESSAGES` in `main.ts` centralizes `class-validator` constraint translations — extend that map rather than hardcoding a per-field message in a DTO. Several literal Vietnamese strings (e.g. `'Không tìm thấy hồ sơ ứng viên'`) are duplicated across 3-5 services with no shared constant (as of Jul 2026) — don't inline another copy; when a new file needs one of these, extract it to a shared constant instead of copy-pasting.
- **BullMQ**: register the queue in its owning feature module, dispatch jobs from the service (never the controller), process in `processors/*.processor.ts`. The global default in `app.module.ts` is `attempts: 3` with exponential backoff — a bare `.add()` call inherits this, only override per-call if a queue genuinely needs a different retry count (e.g. `auth.service.ts`'s email queue already does). A processor's `catch` block must rethrow on error (checking `job.attemptsMade`/`job.opts.attempts` if it needs to distinguish "still retrying" from "final attempt", see `interview.processor.ts`) — swallowing the error makes BullMQ record the job as `completed` regardless of `attempts`. Job payloads should be typed job-data interfaces, not `Job<any, any, string>`.
- **Rate limiting**: `@nestjs/throttler` is wired via `ThrottlerModule.forRoot(...)` in `auth.module.ts` and applied per-handler with `@UseGuards(ThrottlerGuard)` (+ `@Throttle(...)` to override the default) — currently only on `login`/`register`/`forgotPassword`. Follow this scoped, per-handler pattern for any other endpoint that needs rate limiting; don't register a global `APP_GUARD` without deliberately deciding it should apply app-wide.
- **Gemini**: all `@google/genai` calls go through `common/external-apis/gemini/gemini.service.ts` — extend it for new prompts/models, don't instantiate a client elsewhere.
- **Real-time**: emit via `SocketIoService.handleEmit()`; a gateway authenticates the handshake via JWT and delegates both Prisma access and emits to its owning service. Don't hold a second `@WebSocketServer()` instance in a new gateway — `interview.gateway.ts` currently does this and is legacy, not the template (see `anti-patterns.md`).
- **Logging**: no raw `console.*` anywhere in `apps/api/src` (as of Jul 2026) — use a per-class `private readonly logger = new Logger(ClassName.name)` (or a module-scoped `new Logger('ModuleName')` where there's no class instance, see `redis.module.ts`). `GlobalExceptionFilter` logs every 5xx at `.error()` with the stack; don't add a second place that logs 4xx exceptions, they're expected and already client-facing.
- **File upload validation**: don't trust client-supplied `mimetype`/extension alone — Multer's `fileFilter` never has access to real file bytes (confirmed against the installed `multer` version), so content validation must happen post-storage, after the file is on disk. `cvs.service.ts`'s `uploadCV()` checks the real magic-byte signature right after reading the file buffer — follow this pattern (post-storage byte check, not a new dependency) for any other upload endpoint that needs it.
